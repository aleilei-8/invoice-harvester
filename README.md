# 电商订单信息助手（ecom-order-helper）

一款**通用浏览器插件**，给所有电商卖家（拼多多 / 淘宝 / 天猫 / 京东 / 抖音小店 …）用的**开票信息自动抓取 + 本地汇总**工具。解决「每次开票都要逐个复制抬头、税号、订单号、快递单号……」的麻烦：在商家后台打开发票/订单页面 → 点一下插件 → 自动识别列 → 追加进本地汇总库 → 一键导出表格。跨天累积、按订单号去重合并。

> **当前版本 v3.3.5 核心能力**：① 多平台订单/发票页一键抓取（支持「抓取全部页」自动翻页）；② **1688 代发场景**——手动点官方导出后被插件被动捕获入库，弹窗「导出所选订单」按钮**实时联动页面勾选状态**；③ 内置**开票匹配工作台**（`matcher.html`），按**运单号**把 1688 订单与拼多多订单 JOIN，一键生成「按卖家开票清单」与「开票跟踪表」，打通代发开票的最后一公里。

> **合规说明**：本工具**不破解登录、不调用任何私有接口、不绕过反爬**，只读取你已登录的商家后台页面上**已经渲染出来**的表格数据，并保存在你本地浏览器。比「手动逐个复制」更省事，但同样需要你本人登录后台操作。代码完全开源，可自查、可改、可分发。

> **合规与隐私（务必阅读）**：本工具仅读取使用者本人已登录、有权查看的店铺数据，且**数据只存本地、不上传任何服务器**。据此开具发票须真实、金额与实付一致。使用者须：① 遵守各平台商家协议（保持手动触发、只读，不自动轮询）；② 遵守《个人信息保护法》——仅收集**开票必需字段**（抬头/税号/订单号/金额/物品），非必要不抓收货人姓名/电话等敏感个人信息，数据用完及时清理。发票抬头与税号属买家在发票申请中主动提交的信息，卖家据此开票具有合法处理基础。分发本工具不构成法律意见，大额/企业场景建议咨询法务。

## 一、它解决什么

| 你的痛点 | 工具怎么解决 |
|---|---|
| 逐个复制发票抬头 / 税号 / 订单号 | 插件自动识别整页表格，一次抓取几十单 |
| 累计一段时间好多单，登记麻烦 | 本地「汇总库」跨天累积，按订单号去重合并 |
| 发票页没有快递单号，订单页才有 | 分两次抓取，按订单号自动 join 补全 |
| 各平台后台长得不一样 | 内置**多平台列关键词预设**，选平台即自动适配；也能自定义 |
| 要汇总成一个表格 | 插件内联导出 **XLSX**（无需 Python），含「开票明细」+「按抬头汇总」双 sheet；也支持 CSV，或配套 Python 脚本多源合并 |

## 二、安装（Chrome / Edge，开发者模式，零门槛）

适合**任何卖家自己装**，也适合你把它打包分发给其他卖家。

1. 打开扩展管理页：Chrome `chrome://extensions` 或 Edge `edge://extensions`。
2. 右上角打开「**开发者模式**」开关。
3. 点「**加载已解压的扩展程序**」→ 选择本目录。
4. 看到「电商订单信息助手」即安装成功（固定到工具栏更方便）。

> 无需上架商店、无需账号。后续更新只需覆盖目录文件，回到扩展页点「刷新」。
> **分发给他人**：运行 `python build_zip.py` 生成 `ecom-order-helper-chrome.zip`，发给卖家解压后按上面 1–4 步加载即可。

## 三、使用流程

1. **用电脑浏览器登录对应平台的商家后台网页版**（如拼多多 `mms.pinduoduo.com`、淘宝卖家中心、京东商家后台、抖店后台）。
   - ⚠️ 各平台的**桌面客户端（Electron 套壳）里插件无法注入**，请务必用**电脑浏览器**登录网页版。
2. 弹窗顶部「**平台**」下拉选对应平台（拼多多 / 淘宝 / 京东 / 抖音 / 自定义）。
3. 打开要抓的页面（发票记录 / 待开票列表 / 订单查询列表）。
4. 点「**抓取本页**」→ 插件自动识别表格并按表头语义匹配列角色。灰色高亮列即自动识别成功。
   - 点「**抓取全部页**」可**自动回到第 1 页并逐页抓取**，最多 200 页。v2.6 起**抓取循环在网页内运行**（`pagefuncs.js` 注入页面），因此**弹窗可以关闭/失焦，翻页会继续**；每页抓完立即入库（按订单号去重），弹窗重开时会自动接管运行中的任务、绝不重复启动。
     **v2.7 修复「点了抓全部页却只抓到 1 页」**：① 脚本先读分页条拿到「当前页 / 总页数」，**若你停在第 3 页、第 22 页…会先自动点回第 1 页**再开始（这是之前只抓到 1 页的真正原因——从中间页往后翻自然只剩几页）；② 翻页目标改为**在分页条容器内**点「当前页码 + 1」，不再全页面扫数字（旧写法会把「数量 1/3」「消息 17」「站内信 3」当成页码候选而点错）；③ 网页**右上角新增进度浮层**，显示「已抓 N 页 · 当前第 x/y 页」+ 进度条 + 翻页方式，弹窗被浏览器关掉也能看到进度，并可随时点「**停止抓取**」（弹窗里也新增了同名按钮）。结束时会显示停止原因（已到最后一页 / 找不到翻页控件 / 页面未变化 / 手动停止）。
     **v2.8 修复「翻页方式显示了、页面却纹丝不动」**：v2.7 的假设是「点一下就当翻页成功」，在真实后台不成立——浮层明明写着翻页方式，页码却停着不走。真因有三：命中的元素被装饰层盖住（`el.click()` 到不了按钮）、点击处理器绑在 `<li>` 内部元素上（点 `<li>` 无效）、个别组件只认完整鼠标事件。**新逻辑：候选元素按可靠度排序 → 逐个点击 → 每个点完等最多 ~2.4 秒看页面是否真的换页 → 没换就试下一个**；点击时优先点「中心坐标处最顶层的那个元素」（等价真人点击），并在点击前确认「当前页是否已经等于目标页」，避免慢响应导致连翻两页。全部候选都点不动才判失败，并在浮层/日志里列出**已尝试的翻页方式**。
     **v2.9 修复「抓到第 3 页就停（或第 1、第 5 页就停）」**：v2.8 的浮层把**尝试过的方式**打了出来，暴露了真因——`已尝试：pager:[class*="next"]:skipped / pager:[class*="next"]:skipped / scroll`，也就是那一刻**一个页码候选都没有**：分页条重渲染后「页码不再是容器的直接子元素」，箭头又恰好既没有 `next` 类名也没有 `›` 文本，于是候选表空掉、只能去「滚动到底」这条死路。本版四处加固：① **分页条三级定位**（「每页 N 条」文案锚点 → 结构法 → 全页面纯数字共同祖先），文案锚点法还能保证认到**同时包含页码和箭头的那一层**；② **位置法**新增「最大页码之后的下一个元素」（先同级、再沿父级往上），图标型箭头也能被抓到；③ 候选表最后加**全局数字兜底**（非表格内、非浮层内的「目标页码」元素）与「**强制轮**」（连被判 disabled 的候选也点一次——很多自研分页器的 disabled 只是加了个样式，点击处理器仍在）；④ **翻页验证改用「订单号指纹」**（页面上的 `260708-334286067311450` 序列），不再用文本签名——文本签名会被时间戳/角标噪声骗到，出现「同一页被当成三页」的假成功；同时新增**假翻页检测**（连续两页订单号完全相同 → 立刻停止并说明，不重复入库）与**跳页保护**（目标第 2 页却跳到第 9 页且点不回 → 停止并说明，绝不静默漏页）。
     翻页候选优先级：**分页条内目标页码** → 当前页右边的下一个页码/箭头（结构位置）→ 分页条内 `next`/`arrow`/`forward` 类名或语义属性 → 分页条内箭头文本（含其父 `<li>`）→ **最大页码之后的下一个元素（位置法）** → 分页条末尾元素 → 全局 `next` 类名/属性 → 全局箭头文本 → 「当前激活页码 + 1」 → **全局目标页码兜底** → 跳页输入框 → 滚动到底（无限滚动兜底）；翻页后等到内容**变化并稳定**才继续，避免抓到渲染中途的空表。
   - 拼多多「订单查询」页**每个订单是独立表格**（订单编号行 + 商品行），物流行可能在**表格内第二行**、也可能渲染在**表格之外**（不同订单组件不一样）。插件三路并取：① **以订单表格为锚点就近搜索**（向上找只含本单编号且能解析出运单号的容器 + 兄弟节点扫描，与 DOM 结构无关）；② 页面可见文本按「订单编号窗口」配对；③ **宽松兜底**（公司名为英文、标签不是「物流信息」时，在物流标签之后找靠前的长数字串）。输出 **订单号 / 订单状态 / 物品名称 / 快递公司 / 快递单号** 五列（快递公司与单号分两列）。
     繁体支持：港澳台/跨境件常写作 `極兔速遞HK`、`圓通速遞`，插件已支持繁体公司名并**统一输出简体**（→ 极兔速递 / 圆通速递）。
     物流行真实原文（注意**单号与「复制」之间没有空格**）：`物流信息：申通快递 773430693399235复制 已签收，签收人凭取货码签收。…` → 快递公司=`申通快递`，快递单号=`773430693399235`。
     集运仓分段物流（一段 `邮政快递包裹 9901234567890复制` + 二段 `集运仓 消夷香（二段物流） 极兔速递HK JT0024585595081复制`）也能识别：两个物流段都归属同一订单，剥离 `HK` 等路由标识，多段用「、」连接。
     误抓防护：运单号必须**紧跟**在快递公司名之后才会被采纳，因此行文里的电话（`17770199665`、`13142390000`）不会被当成单号；同理「联系**兔兔快递**员（江千红…）」「（**二段物流**）」这类含快递/物流字样但后面是电话或中文的词，也不会被误判成快递公司。
5. 个别列识别错 → 在下拉框手动改成正确角色。
6. 确认无误 → 点「**追加到汇总库**」。多天、多页面重复操作，数据累积并按订单号合并。
   - **推荐工作流**：先在「订单查询」页点「抓取全部页」（拿到订单号/物品/状态/物流），再在「订单开票」页点「抓取全部页」（拿到抬头/税号/金额/发票种类等）——两组数据按订单号**自动合并成一张完整表**。
7. 需要时点「**导出 XLSX**」即可一键生成 `电商订单信息汇总_日期.xlsx`，内含两个 sheet：「开票明细」（全部记录）+「按抬头汇总」（同一公司多笔自动合并、按合计金额降序、含笔数/合计/订单号清单）。默认勾选「含抬头汇总」；只想导出明细时取消勾选即可。非技术卖家无需装 Python。
   也保留「**导出 CSV**」按钮（带 BOM，中文不乱码）。

> **按抬头分组统计**：给同一家公司开了多张发票（多个订单）时，「按抬头汇总」sheet 会自动合并成一行，显示该公司**总笔数、合计金额、订单号清单、物品清单**，并按合计金额从高到低排序，方便按客户对账与统计。未填写抬头的记录单独归为「(未填写抬头)」组。

汇总库条数实时显示；「清空库」可重置（有确认弹窗）。

## 三-2、1688 代发采购模式（被动捕获 + 联动导出，v3.3.5 定稿）

> 适用场景：你在 1688 做**代发采购**，需要把全部 1688 订单的「订单号 / 卖家公司名 / 物流公司 / 运单号 / 实付款」抓出来，再与拼多多抓取器抓到的订单**按运单号 JOIN** 找供应商开票（匹配逻辑见下一节「开票匹配工作台」）。

**为什么放弃自动翻页、改为被动捕获**（这是 v3.3.5 的核心设计决策）：1688 订单列表的真实卡片渲染在**跨域 iframe `g.alicdn.com`** 里，`pagefuncs.js` 受 CSP / 跨域限制**读不到**；运单号也不在列表行内，只藏在官方「导出所选订单 / 导出当前条件」的下载文件里。早期版本（v3.1~v3.2）试过「自动翻页 + 驱动官方导出」，结果既抓不全、又因反复触发导出把浏览器下崩（一次导出 12 份）。**故 v3.2.0 起彻底移除 1688 自动导出，改为：你在 1688 页面手动点官方导出 → 插件在后台用 `chrome.downloads` 被动捕获下载的 xlsx → 自动解析入库**。稳定、零崩溃、数据 fidelity 最高（与官方导出完全一致，含运单号）。

**1688 官方两种导出模式**（弹窗已拆成独立「1688 专区」与「拼多多 / 通用区」两块，互不干扰）：
| 模式 | 含义 | 插件「1688 专区」按钮 | 行为 |
|---|---|---|---|
| 导出所选订单 | 只导出**当前页已勾选**的订单（1688 不支持跨页选择） | 「导出所选订单」 | **联动页面勾选状态**：未勾选则按钮置灰并提示「请先在 1688 选择要导出的订单」；勾选后自动变亮（v3.3.3~3.3.5 经四次迭代根治「误灰」，采用 fail-open 判定 + 2.5 秒实时轮询 + 命中页面置灰副本自动改点亮按钮） |
| 导出当前条件 | 按顶部筛选条件导出（筛「全部」= 全量导出） | 「导出当前条件」 | 直接触发官方导出，**单份下载**（v3.3.5 修了「点一次下两份」——`clickEl` 去掉重复合成事件、只在「生成新报表」弹窗真正可见时才补点） |

**完整使用步骤（1688 代发对账）**
1. 浏览器打开 1688「已买到货品」订单列表页（`*.1688.com`），**等列表完全加载**（出现订单卡片 + 底部导出按钮）。
2. 插件平台下拉选「**1688**」→ 在 1688 页面**勾选**要导出的订单（或顶部筛选「全部」）→ 点页面官方「导出所选订单 / 导出当前条件」→ 等待浏览器下载完成一个 xlsx。
3. 插件后台**自动捕获**该 xlsx，`chrome.downloads` 事件触发 → 按 `A1688_KW` 关键词归列（订单号 / 卖家公司 / 物流公司 / 运单号 / 实付款 …）→ 去重入库「1688 库」（弹窗「1688 库」区实时显示条数；「清空 1688 库」可重置）。
4. 拼多多侧：平台切回「拼多多 / 通用」→ 在订单查询页「抓取本页 / 抓取全部页」→ 入库「拼多多库」（`PDD_KW` 归列：快递单号 / 快递公司 / 抬头 / 税号 …）。
5. 打开**开票匹配工作台**（`matcher.html`，下一节）→「从插件库载入 1688」「从插件库载入拼多多」→ 自动按**运单号归一（去空格、转大写）**作为 JOIN 键匹配，辅助校验快递公司一致，生成「开票清单（按卖家）」「开票跟踪表」。

> 实测：一份 1688 全量报表（约 1279 行）被动捕获后离线匹配，命中约 330 条拼多多订单，直接锁定该找哪家 1688 供应商开票。

## 三-3、开票匹配工作台（1688 ↔ 拼多多，按运单号 JOIN）

> 这是代发开票的「最后一公里」：买家在拼多多申请开票（抬头 / 税号）→ 你作为拼多多卖家要按**快递单号 + 快递公司**找到对应的 **1688 订单号** → 把开票信息发给 1688 卖家开票 → 回填状态 → 把发票上传回拼多多。

直接用浏览器打开仓库里的 **`matcher.html`**（无需服务器、无需联网），它是一个独立的工作台：

- **「从插件库载入 1688」/「从插件库载入拼多多」**：一键把插件本地库（`chrome.storage.local` 里的 `a1688_orders` / `pdd_orders`）读进来，免去手导 CSV。
- **双键匹配**：主键 = 1688 运单号 ↔ 拼多多快递单号（去空格大写归一）；辅键 = 快递公司一致性（归一后包含判定，容忍「极兔速递 / 极兔」这类简称差异）。
- **列角色自动识别**（`buildColRole`）：上传的历史 xlsx 也认，角色白名单含 `status`，状态列不再静默丢失。
- **开票清单 _ 按卖家**：按 1688 订单号去重 + 小计，一眼看清「每家供应商要开多少、合计多少」。
- **开票跟踪表**：记录每单开票状态（待开票 / 已开票 / 已收票），支持按 Sheet 名识别历史结果**回填**（自动排除「小计」行），迭代干活不丢进度。
- **导出**：生成「开票明细 + 按卖家小计 + 开票跟踪」的可交付报表，直接发给 1688 供应商或内部对账。

典型闭环：**拼多多抓全部页 → 1688 手动导出被被动捕获 → 工作台双键匹配 → 按卖家生成开票清单 → 回填状态 → 上传发票**。

## 四、多平台预设 + 自定义关键词

不同平台后台表头措辞不同（如淘宝叫「宝贝标题」、京东叫「商品名称」、抖音叫「物流单号」）。插件内置四套预设，选中即生效；若你的后台有特殊表头，**选「自定义」可编辑关键词 JSON 并保存**：

```json
{
  "buyer_title": ["发票抬头", "抬头", "公司名称"],
  "tax_no": ["税号", "纳税人识别号", "统一社会信用代码"],
  "order_id": ["订单号", "订单编号", "单号"],
  "tracking_no": ["快递单号", "物流单号", "运单号"],
  "amount": ["金额", "价税合计", "实付金额"],

```

匹配规则：**最长命中关键词优先**（例如「订单编号」优先于「编号」），可加英文别名（`tax` / `order` / `tracking`）应对英文表头。保存后立即对下次抓取生效，存在本地浏览器。

## 五、配套 Python 汇总器（生成正式报表）

多份插件导出 CSV，或想把插件数据和平台自带导出的订单 Excel 合并成一份带格式、带金额合计的报表时，用 `invoice_aggregator.py`：

```bash
python invoice_aggregator.py -i ./抓取导出 -o 开票汇总.xlsx
python invoice_aggregator.py -i 发票页.csv 订单页.csv -o 开票汇总.xlsx
```

功能：按订单号合并去重、识别各种表头别名、金额去符号转数值并合计、输出 `.xlsx`（蓝色表头、冻结首行、金额两位小数、合计行）。依赖 `openpyxl`（`pip install openpyxl`）。

## 六、输出字段（顺序）

`发票抬头 | 税号 | 发票种类 | 发票类型 | 其他信息 | 订单号 | 订单状态 | 售后状态 | 成交时间 | 数量 | 商品总价 | 金额 | 快递公司 | 快递单号 | 物流信息 | 收货信息 | 物品 | 开票时间 | 申请时间 | 买家 | 备注`

> v2.4 起订单查询页只抓 **订单号 / 订单状态 / 物品 / 快递公司 / 快递单号**（快递公司与单号分两列；收货信息、买家等不再抓取）。
> 「其他信息」来自拼多多发票页的「其他信息」列（开户银行/账号/地址/电话，买家开票时主动提供）。
> 「订单状态 / 快递公司 / 快递单号 / 物流信息」来自订单查询页（或发票页若有）；发票页提供抬头/税号/金额/发票种类等。两组按订单号自动 join。

## 七、限制与注意事项

- **仅网页版后台可用**：各平台桌面客户端注入不了，请用电脑浏览器登录。
- **需页面已加载完成**：抓取前确认表格已渲染；分页列表可点「**抓取全部页**」自动翻页（也可逐页手动抓）。
- **域名权限已收窄**：`manifest.json` 的 `host_permissions` 仅授权主流商家后台域名（拼多多/淘宝/天猫/京东/抖音/快手/1688）。若用其他平台，在 `manifest.json` 自行追加对应域名后刷新扩展即可。最小权限原则，审计更干净。
- **数据安全**：数据只存本地浏览器 `chrome.storage.local`，不上传任何服务器；换电脑/重装不互通，重要数据及时导出备份。
- **平台改版**：表头大改导致识别失败时，选「自定义」改关键词或下拉框手动指定即可，不影响抓取。
- **发票合规**：抓取仅用于你自己的开票登记与对账，请按税务要求如实开具。

## 九、官方 API 接入探测（可选升级，适合企业店自建）

想把「页面抓取」升级为「官方 API 拉取」（更稳定、可定时自动化），先用 `pdd_invoice_probe.py` 验证接口返回字段与权限：

1. 复制 `pdd_config.example.json` 为 `pdd_config.json`，填 `client_id` / `client_secret` 与 `access_token`（店铺主账号 OAuth 授权）。
2. `shops` 可放多个店铺（企业店 / 个人店对比权限差异）。
3. 运行 `python pdd_invoice_probe.py`，调用 `pdd.invoice.application.query` 并打印完整响应，自动标注「抬头 / 税号 / 订单号 / 金额」是否命中、是否脱敏。

> 发票类属敏感接口，应用需**企业认证**；个人开发者通常无权限（脚本以 `error_response` 体现）。探测仅做可行性验证；正式接入需改成**本地工具保管密钥 + 店铺 token 调用**，绝不能把 `client_secret` 放进浏览器插件。
